The idea

Anatomy from the diffusion scan itself.

Mapping anatomy for a diffusion study has usually meant a second, T1-weighted scan, registered into diffusion space.

SlicerDDSurfer works from the diffusion scan. DDSeg labels tissue, DDParcel labels brain regions and DDSurfer builds white and pial surfaces, all in native diffusion space.

Canonical input

sub-01/
  input/
    data.nii.gz
    bvals
    bvecs
    nodif_brain_mask.nii.gz   # optional; generation needs a supported backend

A DWI series, its gradient files and an optional brain mask. DWI and mask must share one voxel grid.

‘No T1-weighted scan’ describes analysis time. The models were trained with labels derived from T1-weighted MRI.

One subject, one space

From one diffusion dataset to six kinds of result.

Every image here is a frame from the film. Each shows output from one SlicerDDSurfer run on one public dataset: EDDEN, OpenNeuro ds004666, subject sub-01 (CC0). The input is EDDEN’s AVG_mag series: five repeated acquisitions, averaged, so its SNR is higher than a typical single scan. The run used the b = 0 and b ≈ 1000 volumes (117 of 297).

Workflows

One module, five workflow families.

Select only the products you need. Install dependencies for the route you select, not for every possible product.

01

Input preparation

Products
DICOM/NIfTI/NRRD import, gradient validation, optional mask generation and preprocessing
Needs
Appropriate import/preprocessing backend

02

Anatomical reconstruction

Products
DDSeg tissue labels, DDParcel regions, DDSurfer white/pial surfaces
Needs
Matching model assets, PyTorch and SlicerDMRI for the selected route

03

Microstructural analysis

Products
DTI FA/MD/AD/RD, optional Free-water, NODDI and DKI, regional summaries
Needs
Route-specific packages and acquisition suitability checks

04

White-matter pathways

Products
DTI/CSD tractography, ACT/SIFT2, SAF, WMQL/WMA/TractCloud bundles
Needs
Backend-specific tools and assets

05

Structural connectivity

Products
Regional matrices, Slicer scene inspection, QC and provenance
Needs
Compatible parcellation and tractogram; SIFT2 weights for weighted routes
  • Microstructure runs DTI only by default. Free-water, NODDI and DKI are each enabled independently under Advanced.
  • MRtrix3, FSL, FreeSurfer and advanced bundle backends are optional and are not installed silently.
  • A missing backend is reported, never silently replaced.

In 3D Slicer

One 3D Slicer module, with QC and a record of every run.

A run in six steps

  1. Open SlicerDDSurfer from the module selector and choose English or Chinese.
  2. Enter the Subject ID, the subject root and, if you like, a separate output directory.
  3. Tick only the products you need.
  4. In Advanced settings, set routes, dependencies and models, and check the environment.
  5. Click Run SlicerDDSurfer. Missing inputs turn red; the log says what to correct.
  6. Key results from successful stages load into the scene. Review QC, reload, replace or clear them in Advanced settings › Results and QC.

From the command line

Check inputs and the environment without running any algorithm:

shell
python3 run_subject_pipeline.py --subject-root /path/to/sub-01 --targets validation,microstructure --microstructure-stages dti --doctor

Use --plan instead of --doctor to write a run plan.

Status

Research software, stated plainly.

Recorded

  • Linux real-data and GUI evidence is documented for specific checkouts, routes and datasets.
  • The compact interface has its own UI validation record.

Not certified

  • Native Windows and macOS scientific workflows.
  • Three-platform SDK builds.

Not yet released

  • Private pre-release; not in the official Extensions Catalog.
  • The Extension Index JSON is a draft Tier 1 proposal, not a submitted catalog entry and not acceptance by Slicer.
  • Public source access, third-party licence clearance and asset redistribution review remain release gates.

Implementation origins

DDSeg is a MATLAB-to-Python/PyTorch reimplementation. SAF and MK-Curve are unofficial Python ports of author MATLAB methods. PNL CNN masking invokes the author’s existing Python backend, not a rewritten PNL pipeline. DDSurfer runs bundled upstream Python code.

Implementation provenance and verification limits

A completed run is not a clinical assessment or proof of scientific correctness.

Get started

Install from source.

The repository and its model-asset repository are private during pre-release. Use an authorized checkout; links into the repository need access.

  1. Stage the extension

    bash
    git clone https://github.com/ChengjinLii/SlicerDDSurfer.git
cd SlicerDDSurfer
python3 scripts/stage_slicer_extension.py \
  --install-root ~/SlicerDDSurfer-extension --link-mode copy --clean

    Set --slicer-version to your Slicer version. This is a source/staging installation, not an official CPack release.

  2. Add the module path

    In Edit › Application Settings › Modules, add the expanded absolute path of ~/SlicerDDSurfer-extension/SlicerDDSurfer/lib/Slicer-5.10/qt-scripted-modules to Additional module paths, then restart Slicer. Local GUI validation uses Slicer 5.10.

  3. Add the extensions your routes need

    Install SlicerDMRI and PyTorch from Slicer’s Extension Manager.

  4. Get the model files

    Review the asset terms first, then download only the profile you need to a writable folder outside the checkout:

    bash
    python3 scripts/download_model_assets.py --profile surface \
  --asset-root ~/SlicerDDSurfer-model-assets --source url \
  --source-id slicerdsurfer_models_git

    Availability and SHA256 verification do not establish redistribution rights.

  5. Prepare the input

    Use the canonical layout shown above. Gradient files must match the DWI measurements; corrected gradients must accompany motion-corrected DWI.
