B也可以手动配置

  1. 安装插件

    先安装 3D Slicer，本方案参考版本为 5.10。克隆源码并创建独立的插件安装目录：

    bash
    git clone https://github.com/ChengjinLii/SlicerDSpace.git
cd SlicerDSpace
python3 scripts/stage_slicer_extension.py \
  --install-root ~/SlicerDSpace-extension --slicer-version 5.10 \
  --link-mode copy

    将 5.10 替换为 Slicer“关于”窗口中显示的主次版本号。脚本会部署模块并报告安装目录。

  2. 添加模块路径

    打开 Edit › Application Settings › Modules › Additional module paths，添加以下目录展开后的绝对路径： ~/SlicerDSpace-extension/SlicerDSpace/lib/Slicer-5.10/qt-scripted-modules，并与部署时选择的版本号保持一致。

    通过 Slicer 的扩展管理器安装 SlicerDMRI 和 PyTorch。如需使用 UKF，还要安装独立的 UKFTractography 扩展。重启 Slicer 后打开 Modules › Diffusion › SlicerDSpace。

  3. 准备被试输入

    填写 Subject ID 和 Subject root。已准备好的输入采用以下目录结构；输出目录留空时使用被试目录下的 outputs/ 文件夹。

    sub-01/
  input/
    data.nii.gz
    bvals
    bvecs
    nodif_brain_mask.nii.gz   # optional; supply or generate

    DWI 与脑掩膜必须使用相同体素网格。梯度数量应匹配 DWI 的体积数，运动校正后的影像需要配套旋转后的梯度。

    对于 DICOM 或 NRRD/NHDR，在 Advanced settings › Regions & input import › Input import / conversion 中预览导入，再准备标准化输入。

  4. 选择方法并准备环境

    首次试运行可只选择 Microstructure，取消其他产品，并在其“...”选择器中保留 DTI。需要更多分析时，可在各产品旁选择一种或多种算法；模型和追踪参数位于 Advanced settings。

    打开 Environment and installation › Prepare selected analysis environment，确认所需工具、模型和资源许可。下载资源会校验并缓存；如提示重启，重启后再次选择 Prepare 继续。

    离线模型导入、修复和手动路径设置位于 More options。只运行 DTI 时，提供已复核的脑掩膜即可省去掩膜生成后端。

  5. 运行并检查

    点击 Run SlicerDSpace。未填写的必需项会高亮，日志显示进度或具体修正提示。成功生成的关键结果自动加载到场景；DTI 提供 FA 和 MD 供检查。

    在 Results and QC 中选择运行记录，查看检查结果并重新加载或替换输出，避免重复场景节点。接受结果前应复核掩膜覆盖、对齐及方法对应的 QC。

C命令行运行与队列批处理

在代码目录中使用 Slicer 的 Python 检查 DTI 路线，先替换以下两个绝对路径：

bash
export SLICER_LAUNCHER="/path/to/Slicer"
export SUBJECT_ROOT="/path/to/sub-01"
"$SLICER_LAUNCHER" --launch PythonSlicer run_subject_pipeline.py \
  --subject-root "$SUBJECT_ROOT" --subject-id sub-01 --no-user-config \
  --targets microstructure --microstructure-stages dti --doctor

将上述选项换为 --plan 可查看处理计划，再使用 --execute 执行。三条命令的算法选项应保持一致。

例如， --microstructure-stages dti,noddi 选择两个微结构模型； --tractography-backend csd_act,ukf 选择两种追踪方法； --bundle-backend wmql,wma 选择两种纤维束方法。运行前仍会检查各方法的输入与依赖。

对于独立被试，可使用 scripts/run_batch_pipeline.py --batch-root /path/to/study --jobs 2 并添加所选分析参数。GUI 处理当前被试，批处理命令为各被试维护独立输出和日志。
