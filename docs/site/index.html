3D Slicer module · Diffusion MRI

SlicerDDSurfer: a T1-weighted-image-free 3D Slicer workflow for diffusion MRI anatomy, microstructure and connectivity analysis

SlicerDDSurfer builds tissue labels, brain regions and cortical surfaces from diffusion MRI, with no T1-weighted scan at analysis time. It also maps microstructure, traces white-matter pathways and builds structural connectomes.

Workflows

Six connected analysis domains.

From input preparation to regional connectivity, following the protocol. Select the methods your study needs; the workflow resolves their dependencies and reuses shared preparation.

01

Preprocessing

Products
DICOM, NIfTI or NRRD import; gradient checks; brain mask; optional denoising and motion/distortion correction
Needs
Matched image and gradients; PNL CNN, SynthStrip, MRtrix or a supplied mask

02

Microstructure

Products
DTI FA/MD/AD/RD; optional free-water, NODDI and DKI/MK-Curve; regional summaries
Needs
Model-appropriate shell and direction sampling; the plan checks eligibility before fitting

03

Anatomy

Products
DDSeg tissues, DDParcel regions and DDSurfer white/pial meshes; optional thickness, curvature and surface atlas mapping
Needs
Model assets and PyTorch; the licensed native component runtime for surface post-processing

04

Tractography

Products
DTI deterministic, UKF or CSD/ACT tracking; optional SIFT2 weights and surface-constrained SAF
Needs
Selected backend and anatomical inputs; UKF is called through the installed UKFTractography extension

05

Bundles

Products
WMQL anatomical queries, WMA ORG-atlas clustering or TractCloud learned bundle labels
Needs
Compatible tractogram and method resources; the UKF-to-WMA handoff runs automatically

06

Connectome

Products
DDParcel node tables, streamline-count and SIFT2-weighted matrices; optional scalar/length summaries through the Python API
Needs
Matched nodes and tracks; SIFT2 weights from the corresponding CSD/FOD tractogram
  • Defaults: DTI, CSD/ACT and WMQL. Use ... beside each product to select one or several methods; Advanced settings holds detailed parameters.
  • Prepare selected resources under Environment and installation. External tools and model assets are not installed silently.
  • A missing backend is reported, never silently replaced.

Choosing routes

Which route when.

In 3D Slicer

One 3D Slicer module, with QC and a record of every run.

A run in six steps

  1. Open SlicerDDSurfer and choose English or Chinese.
  2. Enter the Subject ID, the subject root and, optionally, an output directory.
  3. Tick only the products you need.
  4. Use ... beside Microstructure, Tractography or Bundles to select one or several algorithms. Prepare resources in Environment and installation; set detailed parameters in Advanced settings.
  5. Click Run SlicerDDSurfer. Missing inputs turn red; the log says what to correct.
  6. Key results of successful stages load into the scene. Review QC, reload, replace or clear them in the separate Results and QC section.

From the command line

Check inputs and environment without running anything:

shell
/path/to/Slicer --launch PythonSlicer run_subject_pipeline.py \
  --no-user-config --subject-root /path/to/sub-01 --subject-id sub-01 \
  --targets microstructure --microstructure-stages dti --doctor

Use --plan instead of --doctor to write a run plan.

Get started

From installation to your first result.

The repository is private during pre-release; you need access to clone it or open its links.

  1. Install the module

    Start with 3D Slicer; the protocol reference is version 5.10. Clone the source and create a separate extension installation:

    bash
    git clone https://github.com/ChengjinLii/SlicerDDSurfer.git
cd SlicerDDSurfer
python3 scripts/stage_slicer_extension.py \
  --install-root ~/SlicerDDSurfer-extension --slicer-version 5.10 \
  --link-mode copy

    Replace 5.10 with the major/minor version shown in Slicer’s About dialog. The script stages the module and reports its installation directory.

  2. Add the module path

    Open Edit › Application Settings › Modules › Additional module paths. Add the expanded absolute path of ~/SlicerDDSurfer-extension/SlicerDDSurfer/lib/Slicer-5.10/qt-scripted-modules, matching the version you staged.

    Install SlicerDMRI and PyTorch from Slicer’s Extension Manager. Add the separate UKFTractography extension if you plan to use UKF. Restart Slicer, then open Modules › Diffusion › SlicerDDSurfer.

  3. Prepare the subject inputs

    Enter a Subject ID and Subject root. For prepared inputs, use this layout; the output directory can remain empty to use the subject’s outputs/ folder.

    sub-01/
  input/
    data.nii.gz
    bvals
    bvecs
    nodif_brain_mask.nii.gz   # optional; supply or generate

    DWI and mask must share one voxel grid. The gradient count must match the DWI volume count, and motion-corrected images need the corresponding rotated gradients.

    For DICOM or NRRD/NHDR, use Advanced settings › Regions & input import › Input import / conversion. Preview the import, then prepare the inputs before analysis.

  4. Select methods and prepare their environment

    For a small first run, select only Microstructure, clear the other products and keep DTI in its ... selector. For a fuller route, choose one or several algorithms beside each product. Advanced settings contains the model and tracking parameters.

    Open Environment and installation › Prepare selected analysis environment. Confirm the required tools, models and resource terms. Downloads are checked and cached for reuse. If a restart is requested, restart and select Prepare again to continue.

    Offline model resources, repair and manual path overrides are under More options. An existing reviewed mask avoids installing a mask-generation backend for the DTI-only route.

  5. Run and inspect

    Click Run SlicerDDSurfer. Missing fields are highlighted, and the log reports progress or a specific correction. Successful key products load automatically; DTI supplies FA and MD for inspection.

    In Results and QC, select the run to inspect its checks and reload or replace products without duplicating scene nodes. Review mask coverage, alignment and method-specific QC before accepting results.

Command-line execution and cohort processing

From the checkout, use Slicer’s Python to check a DTI-only route. Replace the two absolute paths below:

bash
export SLICER_LAUNCHER="/path/to/Slicer"
export SUBJECT_ROOT="/path/to/sub-01"
"$SLICER_LAUNCHER" --launch PythonSlicer run_subject_pipeline.py \
  --subject-root "$SUBJECT_ROOT" --subject-id sub-01 --no-user-config \
  --targets microstructure --microstructure-stages dti --doctor

Repeat with --plan to inspect the processing plan, then --execute to run it. Keep the same method options for all three commands.

For example, --microstructure-stages dti,noddi selects two models; --tractography-backend csd_act,ukf selects two tracking variants; and --bundle-backend wmql,wma selects two bundle methods. Their input and dependency checks still apply.

For independent subjects, use scripts/run_batch_pipeline.py --batch-root /path/to/study --jobs 2 with your chosen analysis options. The GUI processes the current subject; the batch CLI manages separate outputs and logs.

What the numbers mean

Four different levers.

A larger ratio does not make two experiments comparable.

Implementation

Do the same work once.

Batch equivalent operations. Estimator, initialization, solver, precision and QC thresholds stay the same.

Native threads

Use existing compute capacity.

AMICO’s own threads, not a new NODDI algorithm. Hardware is part of the measurement.

Scheduling

Overlap independent jobs.

FW, NODDI and DKI overlap once their inputs are ready. Default concurrency is one.

Python-port control

Name the real reference.

MK-Curve port changes are compared with earlier Python code, not the author’s MATLAB.

Still open

The boundary of the evidence.

These measurements cover specific Linux inputs and settings. They do not replace independent scientific review.

The JSON is a limited public summary, not private logs or subject data.

  • Whole workflowNo matched end-to-end comparison. Do not add savings or multiply ratios across overlapping stages.
  • GeneralizationSingle pairs, no confidence interval; more subjects and hardware are needed.
