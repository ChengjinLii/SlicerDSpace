## 10 月 25 日：多算法共享准备

这一项属于**工作流层的重复计算消除**，不是把原张量估计算法改得更快。
共享的是相同输入、相同拟合定义的中间产物，不合并各模型的科学假设。

| 准备步骤 | 复用边界 |
| --- | --- |
| DWI／掩膜的 detached header | LS、WLS 共用一次转换；需要时保存正确应用缩放系数的独立数据载荷 |
| 原生张量与六种标量 | 按输入和拟合方式缓存；DDSeg 保留 LS，DDParcel、DDSurfer 和配置匹配的微结构路线共用 WLS |
| 图谱配准及重采样 | 图谱、拟合方式、源格式分别建缓存；DDSurfer 保留训练所需的 1-mm 图谱和 NRRD 标量源 |
| 训练要求的归一化与推理 | 不合并：三种解剖模型的通道、网格、归一化与权重不同 |
| DTI 图导出及 QC | 源与 QC 校验一致时，不因强制重跑可选模型而反复导出；源变化或产物失效仍重建 |
| Free-water、NODDI、DKI | 可共用输入及普通 DTI 前置产物，不共享模型参数或擅自替换各自初始化 |
| 追踪及束分析 | 既有完整 tractogram 可供多个消费者使用；UKF 转换、WMA 配准、WMQL 规则、TractCloud 推理仍独立 |

共享缓存增加操作系统持有的写锁、原子记录和产物 SHA256 检查；输入改变、文件缺失／
损坏或运行中断，不能仅凭路径存在认作命中。原生特征记录包含转换及准备代码版本。
DDParcel 的新记录还绑定归一化输入、模型权重、设置和导出结果，避免只看到一个末尾
文件就跳过任务。没有新记录的历史产品保留历史状态，不冒充重新完成来源认证。

共同转换器已与固定版本的 DDSurfer 转换器对照：b=0 即使带有非零占位方向，也写为
零梯度；带 slope/intercept 的 NIfTI 在需要时正确物化缩放值。这两项是**特定输入的
正确性修复**，不是声称与旧版错误转换逐值等价的性能优化。

100206、149741、877168 三个真实 12³ ROI、每个保留全部 288 个测量，与两次独立的
原作者 CLI 调用相比，张量、b0、六张标量图及几何均完全一致。两个 WLS 消费者从
**两次张量拟合＋十二次标量计算，减少为一次＋六次**。
`scripts/benchmark_shared_preparation.py` 和 `Testing/Python/test_shared_preparation.py`
分别复核真实 ROI 与缩放、损坏、设置变化、写锁及表面接入合同。
全脑独立对照保留一项**失败实验**：两边几何 QC 都通过，但分别估计的仿射变换不同，
表面最大顶点偏差为 1.56–3.91 mm。再次原样执行作者的 BRAINSFit 命令，变换也发生
变化；本机 CLI 的度量采样策略为 Random。不能将这组结果认作等价性或加速证据。

另做固定同一参考变换的受控实验：**重新重采样共享原生图**，实际运行归一化及双半球
表面模型，不复制参考的归一化图或网格。六个模型输入图／affine、四个 white／pial
表面及拓扑完全一致，**最大顶点差为 0**。这证明给定相同变换时的共享接入等价性，
不把独立配准变成确定性算法，不更改作者默认采样设置，也不替代人工解剖审核。
见[冻结证据](benchmarks/shared_preparation_20261025.json)、
`scripts/benchmark_shared_surface.py` 与 `scripts/validate_shared_surface_transform.py`。
不将 ROI 耗时外推全脑，不宣称已证明整条工作流加速或解剖准确率提高。

## 长任务与并发补充

本节区分以下收益，不混称“提出了更快的科学模型”：

| 类别 | 已实现内容 | 可作何种表述 |
| --- | --- | --- |

| 后续计算消冗 | 默认 Free-water WLS 无对角矩阵；WMA 同一 VTK 变换批量调用 | 结果一致、独立于线程数；下文分别标明 ROI 与小配准范围 |
| 并行配置 | AMICO NODDI 原生 1／8 线程 | 使用作者已有多核能力，不是插件原创算法 |
| 工作流调度／消冗 | FW、NODDI、DKI 独立进程并发；避免新鲜 NODDI 任务重复拟合已完成的 FW | 降低路线墙钟时间，不等于单模型算法加速 |

**区域统计的改动：** [实现](../../microstructure/pipeline.py)原先对每个脑区和每个指标
反复生成全脑布尔掩膜、扫描有限值。现在只对正标签位置做一次稳定分组，再在各组内
计算。稳定排序保留原布尔索引的 C-order 体素顺序，所以均值、标准差等仍使用相同
浮点运算及样本顺序；NaN/Inf、脑掩膜、逐指标有效性、空区域与排除计数规则不变。
额外分组索引与标签体素数成正比，没有声称峰值 RSS 下降。

**MK-Curve 的改动：** [张量实现](../../microstructure/mkcurve_tensor.py)缓存张量单项式的
固定组合系数，以及作者 256 方向对应的两个只读积分基。后者每进程只占 **42 KiB**；
不缓存体素预测、原始信号或拟合结果。WLLS、QR 回退、方向、曲线采样、校正阈值、
有效性条件和原始异常值都没有变化。参数提取耗时约减少 29.7%；完整计算块耗时减少
**9.46%–9.97%**，不能把较大的参数阶段比例套到整个 MK-Curve。

**实验协议：** 三个独立真实 HCP 被试，固定优化前文件快照与当前实现，同一进程、
同一输入，每方法一次预热、三次计时，交替执行顺序，表中为中位数。CPU 数值基准的
OMP／OpenBLAS／MKL 线程均显式为 1，仅作用于基准进程，不改插件默认设置。
区域统计覆盖完整 `145 × 174 × 145` 网格、FA/MD/AD/RD/L1/Trace 六张图、脑掩膜、
读取、验证、签名与 CSV/JSON 写出；JSON 除耗时外也一致。

候选中取 64 个有限正信号体素，保留作者全套 **200／201／200 个**合成 b0 采样和
181 次观测。完整块对照包含 WLLS、全曲线、异常检测、校正、参数、有效性与残差，
不含 DWI 解压／输入准备和全脑文件输出。**这是对优化前 Python 版的加速，不是
Python 对原作者 MATLAB 的配对结果，更不等于全脑或完整 pipeline 已获得同等加速。**

原始图像、旧拟合及失败记录均未改变；输入文件哈希复核通过。机器仍有其他工作负载，
没有独占硬件，也没有 Windows/macOS 原生测速或准确率提升证据。详见
[本轮 CSV](benchmarks/compute_optimizations_20261020.csv)和

### WMA：保留作者算法，只消除重复筛选

[缓存实现](../../tractography/wma_registration.py)和[作者入口适配器](../../scripts/run_wma_registration.py)
仅缓存确定性的长度筛选结果。真实图谱含 **1,989,106** 条流线，被试含 **277,875** 条；
原版每轮重复筛选及点复制，缓存版保留图谱和被试两个结果。三个种子仍分别执行作者
随机抽样，原采样索引、配准输入数组和随机状态保持一致，不缓存目标函数、变换或分类。

默认开启 `WMAOrgAtlasConfig.registration_preprocess_cache`，仅在已核实的作者
`filter.py` 和 `congeal_to_atlas.py` 哈希匹配时生效；版本未知则运行未修改的作者路线。
输入／输出 VTK 修改时间或长度条件改变会使缓存失效，请求属性、索引等不同处理时绕过缓存。

当前带内存预算的版本另测 **181.542 s**，对保存的同源作者参考为 **2.94 倍**；
这是使用历史参考的新版验证，不能当成第二组独立配对试验。保留缓存峰值为
**3,374,317,568 字节，约 3.14 GiB**，不是整个 WMA 进程的峰值 RSS。
预算上限为可用内存的四分之一、最高 4 GiB；无法读取内存信息时为 256 MiB。
内存不足会降低命中收益，不降低科学计算要求。Windows/WSL 路线当前不启用该 POSIX
入口优化，macOS 原生科学性能尚未实测。

完整 WMA 的新鲜运行另有 **4664.826 s** 记录，以及 95,755 条束分配的几何一致性核查；
但没有与它严格配对的完整无缓存运行，**不能把 2.96 倍推广为整个 WMA 的加速**。
人工解剖审核仍独立保留。详细背景见[工作流验收](WORKFLOW_GENERALIZATION_20261017.zh-CN.md)。

### DDSurfer：继承上游的后处理优化

此项来自固定 DDSurfer 上游 `c3b2d40`，不是插件独创的表面重建算法。
[多帧映射](../../anatomy/surface/ddsurfer_backend/postprocessing/overlays.py)将 thickness、
curvature、sulcal depth、pial area 一次传给 `mri_surf2surf --split`，避免重复加载
相同配准。每张输出含 163,842 个目标顶点，数值、网格、头部及附加 MGH 字节一致。
上述 **3.80 倍**来自插件保存的同输入真实命令计时，不混用上游其他试验的数字。

同步实现还包括 Python 区域标签导出、进程内统计、跨图谱共享输入和双半球线程预算。
插件对 109 个区域标签及两套统计表做过逐字节核查，但未保存完整的新旧配对耗时，
因此不额外为这些子步骤填加速比。上游另有 warm-file 测试，见其
[优化说明](../../anatomy/surface/ddsurfer_backend/postprocessing/OPTIMIZATIONS.md)，
不能混称为插件全流程测速。球面配准、厚度等科学步骤仍使用所需的 FreeSurfer 算法。

### DWI 读取：避免重复 gzip 解码

[读取工具](../../shared/diffusion_io.py)将 `.nii.gz` 顺序解压一次至临时磁盘，再以内存映射
读取分块；退出后清理临时文件，原始 DWI 不变。真实输入为 `145 × 174 × 145 × 288`，
测试位置为 z = 0、72、144；当时未安装 `indexed_gzip`。只有一对计时，文件系统页缓存
未严格控制，不能推广为所有存储设备上的稳定倍数。

它减少重复压缩读取并控制内存需求，但需要足够临时磁盘；没有测得峰值 RSS 降低百分比，
也没有本轮完整 FW 拟合的新旧配对测速。64 体素 FW 对照数值一致不等于全脑速度已验证。
复现实用脚本为[分块 I/O 基准](../../scripts/benchmark_diffusion_chunk_io.py)。

## GPU 并不保证更快

PNL 当前实际调用作者 Python/TensorFlow CNN 和 ANTs，不是整套 PNLpipeline 的重写。
同输入 CPU 为 **78.961 s**，默认 Auto GPU 为 **84.437 s**，显式 CUDA 重复为
**79.775 s**；默认 GPU 在这组总耗时中反而约慢 **6.94%**。
TensorFlow／H100 启动、JIT、配准、哈希及 b0 准备均可能占时；CNN 可用 GPU
不等于整条掩膜路线都在 GPU 上运行。

旧 CPU **346.70 s** 的完整环境记录不足，不能拿它直接除以新 GPU 时间宣称四倍加速。
SynthStrip 的单对 CPU/GPU 约 1.50 倍是当前可引用的设备测量；其 Dice 是两次输出的
一致性，不是对人工金标准的准确率。CUDA eddy 已有真实运行，但没有同协议配对 CPU
测速，完整预处理约 719 s 也不是 eddy 单独耗时。见[GPU 测量及失败记录](GPU_POLICY_20261013.md)。
