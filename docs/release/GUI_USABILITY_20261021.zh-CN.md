## 本轮处理的问题

此前算法验收使用的环境，不等于用户正在查看的 Slicer 实例。
当前 GUI 原先未配置模型目录、未挂载 PNL 隔离环境，且已安装的 SlicerDMRI 没有正确加载
DTI 模块。该会话的旧报告有 12 项阻碍，不能用另一环境的成功结果把它标绿。

另外，准备入口调用了 Slicer 5.10 PythonQt 未暴露的 `isExtensionLoaded`，可导致点击后异常。
现改用扩展安装状态与实际模块能力，明确区分“已安装”“需重启”“已加载”。
检查器增加当前 GUI 的原生 DTI 模块检查，单纯能导入 `slicer.util` 不再代表 SlicerDMRI 可用。

专用开发会话已补齐明确指定的资源挂载、原生扩展路径与 GPU 暴露；这些是本机会话修复，
不是把服务器私有路径写进插件，也不是证明其他用户设备已配置成功。MRI Agent 会话未重启或修改。

## 操作路径

主界面保留输入、产品选择、运行和日志。三组算法各用一个多选入口；高级参数按类别显示，
不与依赖安装混在一起。

| 场景 | 当前行为 |
| --- | --- |
| 选择被试目录 | 仅为空白 ID 自动填目录名；已有自定义 ID 保留 |
| 误选规范 `input/` | 验证三个原始输入文件存在后，回到其父级被试目录 |
| 检查环境 | 后台进程，可取消；摘要内联显示，不自动弹出长详情窗 |
| 准备环境 | 同一后台检查入口；确有待处理项目才确认，就绪时不重复下载或安装 |
| 运行前检查 | 没有有效缓存时自动后台检查，通过后继续提交；依赖不足停止并指向环境区 |
| 检查中改配置 | 旧结果作废，不用于自动开始新配置的运行 |
| 次要配置 | 离线导入、修复、详情、手工路径折叠在环境区“更多选项” |
| topup 配置报错 | 展开实际可见的高级设置及预处理类别，不再指向隐藏的旧参数区 |
| 成功结果 | 按当前运行记录自动加载代表性产品；同一策略重复加载复用节点 |

已有输出默认仍位于 `<subject>/outputs/`。自动加载只选择代表性产品；手动加载更多产品时，
新增其他参数图不等于重复节点。执行完成、自动 QC、人工审核保持不同含义。

真实 Linux Slicer 5.10、复制安装副本、独立设置与 X 显示用于 GUI 验收；不是仅测试假按钮。
网络关闭的隔离测试不宣称完成了首次联网下载安装。

最终 Python 回归共 1,273 项：1,270 通过、3 跳过。下列六类真实 GUI 验收通过；
脑区测试首次复跑遇到旧夹具目录重名，已改为独立临时夹具，并在新目录通过，
未删除历史失败记录或复用旧结果充当新验收。

| 验证 | 覆盖 |

| `environment_button` | 实际点击、异步返回、Qt 心跳、内联摘要、主动展开详情 |

安装版额外走通一次全新合成输入的“Run 按钮 → 后台检查 → DTI → 确定性追踪 → 自动加载”：
`validation=passed`，`microstructure.dti=completed`，`tractography.dti_det=completed`。
自动加载 AD、FA、MD、RD 和流线，重复自动加载复用节点。
该次检查点击返回约 **0.081 s**；全段记录 229 次 Qt 心跳，最大间隔约 **1.42 s**，
因此不宣称整个 GUI 完全无阻塞，尤其大结果转换和场景插入仍需持续观察。

当前默认所选路线的安装版检查为 **0 项阻碍**。31 个核心资源文件通过可信清单校验；
固定 PNL 环境的三方向模型通过 GPU 前向检查；PyTorch 实际 CUDA 张量运算成功。
UKF 未选择且该会话未安装，不因此宣称所有可选后端已就绪。

本地详细证据位于 `ignore/validation/algorithm_picker_20261021/`：

`live-ux/` 为安装版报告、截图与资源验证日志。
这些文件含本机路径，不作为可再分发人体数据或默认安装资源。

## 边界与后续

这次是 GUI 与依赖可用性验收，不重新认证所有人体科学结果。合成 DTI 不能证明全脑束解剖准确性。
Windows/macOS 原生完整流程、首次下载的网络异常、真实长任务的人机交互仍需各自验收。
SlicerDMRI 读取无张量的流线预览时可能打印 `No data to glyph!`；线几何仍成功加载，
但这一原生显示警告尚未在本轮消除，不标记为全部界面问题已经解决。
