## 本轮修复

基线为 `558a497` 加本地工作树。此前的网站、本地化和插图修改保留，未改写历史基准或提高 QC 通过率。

| 问题 | 处理 | 验证 |
| --- | --- | --- |
| DWI 体积数与梯度数不一致仍通过 | 检查非空 4D 头信息、空间几何和梯度数量 | 4 个体积配 3 个梯度被拒绝；3D 输入被拒绝 |
| `inf` b 值触发异常 | 仅对有限值汇总 shell，结构化记录非有限梯度 | `inf`、`-inf`、`nan` 均得到失败 JSON，不抛转换异常 |
| 校验失败后仍进入推理 | DWI 消费任务在执行前自动校验；按输入依赖标记 blocked | 掩膜 affine 错位、梯度缺项、非有限值在 fresh/resume 两种模式下均不调用 DTI 或 DDSeg |
| DDSeg 损坏产物仍复用 | QC 写入四份输出的 SHA256，复用时重新读取内容核对 | 分割及三个概率图逐一覆盖，即使保留文件大小和 mtime，也不复用 |
| 批次仅按退出码宣布完成 | 读取本次新写入的子 manifest，汇总任务和被试状态 | 真实 CLI 的 WMA-only 受阻运行汇总为 `completed_with_blocks`，默认批次退出码为 2 |

原始 DWI 校验失败不阻断独立的已有束结果检查或表面后处理。元数据错误单独阻断依赖它的预处理。
独立结果仍须满足各自的来源和 QC 检查。

DDSeg 的旧 QC 如果没有输出凭据，下一次运行会重新计算，不能凭旧的绿色状态直接补签。
损坏、来源不符或缺少凭据的文件均不能标为 cached。新增严格内容核验复用公共产物记录实现，
但不使用仅靠文件元数据的摘要缓存。

批次记录新增 `subject_status_counts`、`task_status_counts`、每个子运行的 manifest 和状态来源。
单被试 CLI 允许部分执行的既有规则保留。接受部分批次结果时可显式添加
`--allow-partial-success`；退出码可为 0，受阻状态仍保留。
自定义 `--pipeline-script` 若不实现子 manifest 合同，只能记录进程层面的 `process_completed`。

## 计时范围

旧 `elapsed_seconds` 和 `orchestration_elapsed_seconds` 保留原含义：报告前的快照。
新增字段避免把它误认为完整等待时间：

| 字段 | 范围 |
| --- | --- |
| `wall_time_seconds` | 编排开始至产品执行、报告及最终目录刷新完成，末次遥测写入之前 |
| `phase_timings_seconds` | 规划、输入准备/校验、产品执行、元数据/画像、目录报告、被试报告/刷新 |
| `cli_timing.main_wall_seconds` | CLI 主函数开始至环境检查、规划、编排返回；不含 Python 启动和最终响应写出 |
| 批次 `results[].elapsed_seconds` | 启动子进程至其退出，包括解释器启动和子进程内部报告写入 |
| `directory_statistics` | 各声明输出根路径的统计耗时、文件数和顶层扫描耗时 |

报告失败仍记录耗时；额外回归以 30 ms 人工报告延迟验证新 wall time 包含该区间。
并发任务的秒数不能相加代替墙钟。这里没有新增 GPU 峰值显存或进程树峰值 RSS 采样器。

### 小型测量

运行 `scripts/benchmark_workflow_overheads.py`，三种小型合成输入，每种依次执行首次输出、重复请求和梯度修改，共 9 次。
只运行输入校验及报告，没有 MRI 模型拟合，也不是模型缓存的冷/热对照。下表为三次中位数，单位 ms。

| 场景 | API 完整调用 | 旧报告前快照 | 新编排 wall time | 目录统计 |
| --- | ---: | ---: | ---: | ---: |
| 新输出目录 | 12.63 | 7.23 | 12.10 | 0.38 |
| 同参数重复 | 14.98 | 7.70 | 14.44 | 0.73 |
| 修改梯度 | 15.32 | 7.65 | 14.80 | 0.81 |

原始重复值、源码哈希、CPU 亲和性、线程设置和系统负载保存在[JSON](benchmarks/workflow_overheads_20261030.json)。
共享主机未清空系统缓存。此试验确认计时边界；不能外推全脑速度或构成算法加速证据。

在这个小目录中，扫描开销不足以支持进一步增加缓存复杂度，因此本轮只加入画像，不修改统计结果或缓存科学凭据。
真实的大型结果目录是否值得合并遍历，需用新增计时继续判断。

## 后续取舍

采纳先修可靠性、再补计时边界的顺序。MK-Curve、DKI、WMA 当前版完整配对，连接组端点共享、
FOD 依赖缓存、跨模型 mmap、全局 GPU/RAM 准入仍是候选，不记为本轮已实现或已提速。
本机 H100 的即时利用率仍接近满载，本轮没有启动新的长时间全脑/GPU 性能实验。

下一轮优先在冻结源码与资源预算后补长模块配对，再按真实热点决定是否实施这些候选。
