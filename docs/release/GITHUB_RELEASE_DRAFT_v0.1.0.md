# GitHub Release Draft: SlicerDSpace v0.1.0

Use this draft when creating the GitHub Release page for the existing
`v0.1.0` tag. Do not move the tag silently. If post-tag changes on `main`
should be included in the release, create a new tag such as `v0.1.1` or
`v0.1.0-rc2` after rerunning the release gates.

- Tag: `v0.1.0`

- Draft: recommended until the DOI boundary and asset terms are reviewed

## Body

SlicerDSpace v0.1.0 is the first code/documentation release candidate for an
integrated 3D Slicer workflow covering diffusion MRI-derived anatomical
reconstruction, segmentation, parcellation, microstructure outputs,
tractography, bundle analysis, connectome construction, quality-control review
and provenance capture.

### Highlights

- Manifest-driven model asset download and verification through
  `docs/assets/MODEL_ASSETS.md`, `models/assets_manifest.json`,
  `scripts/download_model_assets.sh` and `scripts/download_model_assets.py`.
- Explicit model-asset terms governance in `docs/assets/MODEL_ASSET_TERMS.md`.
- Release metadata and validation support through `docs/release/RELEASE.md`,
  `docs/release/DOI_ARCHIVE_PREP.md`, `CITATION.cff`, `codemeta.json`,
  `.zenodo.json` and `ignore/releases/v0.1.0`.
- Slicer UI and CLI support for external dependency path overrides,
  target-aware environment checking and conservative dependency installation.
- Representative output-tree and release-validation reporting for the
  100307 release-candidate route.

### Asset And DOI Boundary

This release should be treated as a code/documentation release unless model
asset redistribution and DOI-archive rights are confirmed separately. Local Git
LFS verification proves that the files in a checkout are present and not LFS
pointers; it does not grant public redistribution rights for model weights,
templates, validation fixtures or subject-derived assets.

For DOI deposition, use `docs/release/DOI_ARCHIVE_PREP.md` and publish a code-only archive
unless every asset group listed in `docs/assets/MODEL_ASSET_TERMS.md` has confirmed source,
ownership, license, redistribution permission and archive permission.

## Scripted Creation Command

The repository `Release` workflow can create or update this draft release from
the GitHub Actions page:

1. Open the `Release` workflow.
2. Select `Run workflow`.
3. Set `create_github_release=true`.
4. Optionally set `run_fresh_clone_smoke=true` to attach
   `fresh_clone_smoke_report.json` to the release.
5. Keep `release_tag=v0.1.0` unless preparing a new tag.

This uses the workflow `GITHUB_TOKEN` with `contents: write` permission.

If GitHub reports stale unsuccessful checks after the workflow split, inspect
the latest commit and branch protection with:

```bash
GITHUB_TOKEN=<token> \
  python3 scripts/check_github_ci_status.py \
  --repository ChengjinLii/SlicerDSpace \
  --ref $(git rev-parse HEAD) \
  --branch main
```

Only `CI / fast-checks` or `fast-checks` should be required for push and pull
request CI.

This repository also includes a GitHub REST API helper that creates the draft
release and uploads the default code-only support files from a maintainer
machine. Validate the plan without credentials first:

```bash
python3 scripts/create_github_release.py --dry-run
```

When a maintainer token is available:

```bash
GITHUB_TOKEN=<token-with-repo-release-permission> \
python3 scripts/create_github_release.py \
  --fresh-clone-report /path/to/fresh_clone_smoke_report.json
```

The script defaults to `draft=true` and `prerelease=true`. Add `--publish` only
when the release should be visible immediately, and add `--final` only when this
is no longer considered a prerelease.
