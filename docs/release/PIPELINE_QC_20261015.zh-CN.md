## 修复的问题

| 环节 | 原问题 | 现在的处理 |
| --- | --- | --- |
| DTI | 特征值更新后旧 RD 可能残留 | 随当前导出重算 RD，并检查 AD/RD/MD 关系 |
| DTI 缓存 | 切换 FW/NODDI 也重复复制八张参数图 | 独立输入、输出签名和 QC；未变化时直接复用 |
| FW/NODDI 缓存 | 仅文件存在、可读或旧绿色状态就可能完成 | 要求明确 QC 通过、检查项为真、来源和输出签名未变化 |
| AMICO 输入 | 同一缓存中的旧链接/副本可能指向另一份输入 | 校验、刷新链接；Windows 无链接权限时校验副本 |
| AMICO 核字典 | 已存在字典时上游跳过生成，可能混用协议 | 按输入协议、模型参数及 AMICO 版本隔离；NODDI stage v3 不复用旧缓存 |
| NODDI QC | 写出地图后无条件记完成 | 检查原生空间、有限/有界参数、二值且非空的有效组织、有限非负残差 |
| DKI | 拟合体素不为空但有效定量体素为零仍可能完成 | 发布前失败；旧零有效体素缓存不能复用 |
| Python MK-Curve | 校正有效体素为零仍可能记完成 | 阶段失败；独立审计也拒绝空有效掩膜 |
| 表面后处理 | 完成和缓存主要依据文件存在 | 解码网格对应、厚度/面积、形态学参数、分区和统计；输出或参考脑改变后旧 QC 失效 |
| DDParcel | 缺原生空间导出却仍可能日志记成功 | 原生与配准标签、四张归一化输入全部解码并检查 |
| 束分析审计 | 旧审计只检查非空/总体覆盖 | 完整解码并应用当前逐查询、逐主束采样门禁 |
| 耗时汇总 | 失败但快速的旧束结果可能成为成功代表值 | 失败保留在记录中，但不参加成功计时选择 |

Slicer 的 Trace 来自原始张量，而特征值参数会处理负值。因此 MD 检查的是导出
特征值均值；只有 L3 位于截断边界且 Trace 不大于截断后和时，才允许 Trace 差异。
100307 有 9,894 个脑内体素属于这种情况；MD 与特征值均值最大差仅 4.66e-10。
没有人为修补参数图。[Slicer 源码](https://github.com/Slicer/Slicer/blob/main/Libs/vtkTeem/vtkDiffusionTensorMathematics.cxx)。

## 性能与计时

- DTI 八图导出加 QC：新导出 **1.103 秒**，复用 **0.00125 秒**，文件时间戳未改变；不是张量拟合加速倍数。
- 新 NODDI 全脑拟合 **343.098 秒**；旧单线程记录 **1784.280 秒**。不是严格配对的硬件测速，但数值输出逐体素一致。
- FW 改为一次顺序 gzip 解压、磁盘映射分块读取。真实三切片块的数值、affine 与输入 SHA256 一致；小 ROI 拟合与直接 DIPY 对照通过。尚未重测全脑 FW 拟合总时间。
- 本机没有 `indexed_gzip`，三切片块读取从 **37.252 秒**降到 **17.079 秒**；64 体素真实 FW 拟合与直接 DIPY 完全一致。这不是全脑模型加速倍数。
- NODDI 默认按可用 CPU 自动使用至多 8 线程，显式正线程数仍保留；没有全局禁用 CUDA。
- 只有真实支持 GPU 的后端才使用 CUDA；DIPY/AMICO CPU 路线不冒称 GPU 计算。

[32 项操作耗时表](MODULE_RUNTIMES_20261015.zh-CN.md)注明不同被试、设备、版本和
前置缓存。不能把这些数值求和作为一次完整 pipeline 耗时，也不是所有电脑的时间承诺。
