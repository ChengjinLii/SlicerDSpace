3D Slicer Extension · dMRI Pipeline

3D Slicer 插件项目工作流

面向 dMRI 微结构分析、皮层表面重建、纤维束追踪与连接组分析的统一插件式 pipeline。整体目标是把已有命令行流程、深度学习模型和 Slicer 场景交互整合为一个清晰、可复现、可扩展的工作流。

01
统一编排GUI、参数节点、DAG runner 与工具适配层共同管理流程。
02
三条科学分支微结构、结构/表面/分区、纤维束追踪与连接性分析。
03
结果可追溯输出影像、表面、表格、QC 报告、MRB 场景与 provenance.json。

1. 插件编排层

这一层负责把用户操作、参数配置、流程执行和外部工具调用统一起来，是 Slicer 插件从“脚本集合”走向“稳定产品形态”的关键。

脚本化 GUI / QC 面板用户选择数据、参数预设、查看中间结果与质量控制。
参数节点MRML + JSON job spec，用于保存任务配置和运行状态。
DAG 流程运行器支持依赖管理、断点续跑、缓存、日志和失败恢复。
工具适配层Slicer CLI、Python logic、容器和外部命令的统一封装。
外部计算引擎MRtrix3、FSL、DIPY、DDSeg、DDSurfer、DDParcel、pyAFQ。
MRML 场景与 provenance把结果、显示状态、文件路径、版本信息与报告统一管理。

2. 主流程总览

从数据导入到下游导出，主流程保持线性清晰；复杂建模部分在中间拆分为三个并行但互相依赖的科学分支。

3. 输入 / 输出文件树设计

这一版按“先生成公共底座，再由各 pipeline 复用”的原则重写：DWI 预处理、mask、DTI 标量图、CSD/FOD、结构分割、surface 和 parcellation 都只计算一次；DDSurfer、DDParcel、ACT、tractography 内的 connectome 和区域统计统一从 shared 层读取。

公共底座优先

把 DWI 标准化、denoise、degibbs、eddy/topup、bias correction、mask 与 QC 放入 01_preproc/，后续所有方法共享。

模型图谱集中

DTI 的 FA、MD、AD、RD、L1/L2/L3、Trace 与后续 free-water、NODDI 等稳定产物统一放入 02_microstructure/；可重建的 tensor 原始中间文件留在 cache/。

结构逐级复用

DDSeg 产物支持 DDSurfer；DDSurfer surface / annotation 与 DDParcel wmparc 支持 ACT、tractography 内 connectome 和区域统计。

Native-space 主线

核心建模与分析默认不依赖跨空间配准；模板空间相关结果作为可选扩展产物单独管理。

结果与缓存分离

outputs/ 只放稳定产物；cache/ 放可重建临时文件、容器 workdir、模型中间 tensor。

manifest 可追溯

每个阶段写入 status、输入输出、hash、软件版本和参数，方便 Slicer GUI 恢复、重跑和调试。

命名规范统一

推荐采用 BIDS-like 命名（如 sub-* _space-* _desc-*）；减少长期维护中的语义歧义和批处理脚本分支。

输入树：统一输入契约（建议长期保持）

minimal + compatible
  • <subject_root>/
    • input/
      • data.nii.gz # DWI 主数据，4D NIfTI
      • bvals # b-value 文件
      • bvecs # gradient direction 文件
      • nodif_brain_mask.nii.gz # DWI native-space brain mask
      • data.json # 建议提供：BIDS metadata，含 PhaseEncodingDirection / TotalReadoutTime
      • T1w.nii.gz # 可选：仅用于未来跨模态扩展，不作为主流程前置
    • outputs/ # 可选，运行后自动生成
    • cache/ # 可选，运行后自动生成

复用关系

不要重复计算
FA / MD / AD / RD / L1-L3只在 02_microstructure/dti/ 中生成一次；DDSurfer、DDParcel、regional statistics 读取同一份。
mask / b0 / corrected DWI只在 01_preproc/ 中生成一次；DTI、NODDI、FOD、DDSeg 都复用。
surface / parcellationDDSurfer 输出 white/pial surface；DDParcel 读取 surface 后输出 aparc/wmparc/DKT/Yeo labels。
5TT / GMWMI / FOD只为 tractography 生成一次；whole-brain tractography、bundle segmentation 和 connectome 共用。

为什么 FA / MD 不放进 DDSurfer？

FA、MD 是 DTI 模型公共产物；DDSurfer 只是消费它们或其他共享图谱，不应该拥有第二份拷贝。

为什么 DDParcel 不应强耦合 DDSurfer？

DDParcel 优先复用 shared DTI 底座；surface priors 可作为增强分支，而不是唯一前置条件。

为什么 registered_to_dwi 单独放？

ACT、connectome 和 tractography 都在 DWI/native 空间最稳定，label 必须有一份 in_dwi 版本。

为什么输出里保留 .nhdr？

SlicerDMRI 对 NHDR/NRRD 扩散数据更友好，保留一份可直接加载进 Slicer scene 的格式。

4. 启用条件与关键缩写

插件中建议把这些判断写成显式 gating rules，避免用户在不满足数据条件时误跑模型或得到低可信结果。

流程启用条件

仅多壳层 DWI 才启用 NODDI。
磁敏感畸变校正优先使用反向相位编码 b0 或等价场图信息。
T1w MRI 仅作为可选扩展输入，不是主流程必需项。
DDSeg / DDSurfer / DDParcel 可提供 dMRI-only fallback，但结构结果置信度较低。
