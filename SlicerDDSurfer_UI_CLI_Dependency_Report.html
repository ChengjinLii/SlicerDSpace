slicer workbench

Slicer UI 怎么用

Header 与状态栏

顶部标题是 SlicerDDSurfer Release Workbench， 用来提示当前 UI 是一个统一 pipeline 工作台，不再是单一算法面板。

statusLabel 显示当前状态，例如等待输入、正在检查依赖、后台任务运行中、partial result 或 failed。

面板折叠逻辑

主线只暴露统一工作流面板。旧的单产品面板，例如 DDParcel、DDSeg、Microstructure、Surface Postprocess， 仍在代码中保留，但默认隐藏，避免用户误以为要分散填写多套路径。

0. Environment & Dependencies

组件作用使用建议
Torch device 选择深度学习推理设备：`auto`、`cpu`、`cuda:0`。 默认用 `auto`。doctor 会把 `auto` 解析为一个具体设备，不会 CPU/GPU 两套都跑。
Install missing Python packages 勾选后，Slicer UI 在运行前可以尝试安装缺失 Python 包。 只自动安装 Python 包。MRtrix3、FSL、FreeSurfer、WMA、TractCloud、模型数据不会被静默安装。
Check environment dependencies 运行依赖体检，生成环境报告和安装辅助脚本。 正式运行前先点一次。结果会更新可跑 target、blocked target 和路径状态。
Advanced external paths 配置 MRtrix3、FSL、FreeSurfer、TractQuerier、WMA、Slicer executable、TractCloud 等外部路径。 留空表示不提供用户覆盖路径；doctor 会按环境变量、PATH 和常见安装目录做确定性发现，不会全盘递归搜索。显式路径会保存到 Slicer user settings，下次打开自动恢复。
Import / Export dependency config 导入或导出与 CLI 兼容的 JSON 路径配置。 适合在 Slicer UI 和终端命令之间复用同一套外部依赖路径。

1. Subject Setup

Subject ID：被写入 manifest、报告、输出文件名和 run metadata。留空时 CLI 通常使用 subject root 的目录名。

Subject root：推荐输入目录，必须包含标准输入文件。

<subject_root>/input/data.nii.gz
<subject_root>/input/bvals
<subject_root>/input/bvecs
<subject_root>/input/nodif_brain_mask.nii.gz

Output directory：可选。留空时默认写到 <subject_root>/outputs。

Selected products summary：自动显示当前勾选的 targets 和 backend 组合，帮助运行前确认。

Target products

目标输出/含义主要依赖
PreprocessingDWI denoise、Gibbs、motion/eddy 预处理；也支持 fast path 直接链接原始输入。DIPY 或 MRtrix3/FSL。
SegmentationDDSeg WM/GM/CSF segmentation 和 probability maps。PyTorch、SlicerDMRI DTI features、`segmentation/weights`。
ParcellationDDParcel aparc/wmparc 标签。PyTorch、Slicer CLI registration/DTI、`parcellation/weights`。
SurfaceDDSurfer white/pial cortical surfaces。PyTorch、DDSurfer checkpoints、templates、atlas。
MicrostructureDTI FA/MD/AD/RD/L1/L2/L3/Trace，ROI 统计，可选 Free Water 和 NODDI。DIPY，NODDI 需要 AMICO。
TractographyDTI deterministic、MRtrix CSD/ACT 或 SAF。MRtrix3 或 DIPY，SAF 需要 surface fixture。
BundlesWMQL、WMA 或 TractCloud bundle extraction。TractQuerier、WMA ORG atlas、TractCloud model 视 backend 而定。
ConnectomeStreamline-count 和 scalar/SIFT2 weighted connectivity matrices。已有 tractogram、parcellation；MRtrix backend 需要 `tck2connectome`。

Advanced run settings

Run name：用于组织 tractography、bundle、connectome 和 run metadata 子目录。例如 `rc_csd_act`。

Tractography backend：`csd_act` 用 MRtrix CSD/FOD/ACT；`dti_det` 用 DIPY deterministic tracking；`saf` 先跑 CSD/ACT 再做 SAF surface filtering。

Bundle backend：`wmql`、`wma`、`tractcloud` 或 `all`。`all` 会展开成多个 backend，缺依赖的 backend 只会 blocked。

ACT streamlines：MRtrix ACT 请求 streamline 数，默认 100000。

Microstructure stages：`dti`、`dti,freewater` 或 `dti,freewater,noddi`。Free Water/NODDI 是长任务，不建议放在 quick gate 里。

Preflight and run selected products：先跑 dependency doctor，再用后台 `QProcess` 调统一 CLI，不阻塞 Slicer 主线程。

Run Plan & Progress

点击运行后，UI 会生成并展示 run plan。表格列含义如下：

列含义
Target任务名称，例如 `segmentation.ddseg`、`tractography.csd_act`。
State`will_run`、`running`、`completed`、`skipped`、`blocked`、`failed`、`cancelled`。
Reason为什么运行、跳过、blocked 或失败。
Manifest / QC / Logs双击可打开对应文件或目录，便于定位每个子任务结果。

`Open latest report` 会打开最新 HTML 结果报告。`Cancel running job` 会停止后台进程，并写入 cancelled manifest。 `Pipeline Log` 保留最新 4000 行，避免长日志拖慢 Slicer UI。

dependency doctor

依赖如何扫描，如何安装缺失项

扫描对象

依赖不是全局一次性检查，而是根据 selected targets 和 backend 组合动态构建。

Python imports external commands env vars model paths CUDA device user settings

发现顺序

外部工具路径按以下优先级解析：

用户保存路径或 CLI config - 环境变量 - PATH - 常见系统路径。

这里的“自动发现”不是扫描整个磁盘；如果工具装在自定义目录且没有加入 PATH/环境变量，就需要在 UI 里填写路径或导入 dependency config。

命令类依赖会记录 `detected_source`、`resolved` 和 `checked_locations`。

依赖类别检测方式缺失时如何处理
Python 包 用当前 Python 或指定 `--doctor-python-executable` 执行 import probe。 写入 `install_missing_python.sh` 和 `install_missing_python.ps1`。UI 勾选自动安装时只安装这些包。
MRtrix3 / FSL / FreeSurfer / WMA 命令 检查用户路径、环境变量、PATH、常见路径。 写入 `install_external_tools.md`，不会静默安装，因为涉及平台、license 或管理员权限。
模型权重和模板 检查 Git LFS 下载后的目录或文件是否存在且非空。 提示运行 `scripts/download_model_assets.sh --profile core` 或针对 profile 下载。
CUDA 设备 在目标 Python 中检查 `torch.cuda.is_available()` 和 device count。 选择 CPU，或安装可见的 CUDA PyTorch runtime；严格选择 cuda 时 target 可被 blocked。
WMA / TractCloud 数据 检查外部 checkout、atlas/model data、专用 Python executable。 作为 optional external backend 交付，必须由用户显式配置。

当前默认是 partial execution：缺依赖的 target 被写入 manifest，状态为 `blocked`，依赖齐备的 target 继续运行。 如果需要任何 selected target 缺依赖就完全停止，添加 `--strict-environment`。
